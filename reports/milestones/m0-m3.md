## 3. 设计边界与后续可选（不是产品未完成）

- M2 定位为**本地、loopback、文件模式旁的可选控制面**：不托管 run 进程、不做自动心跳、不做备份/迁移、不做 config mode 切换；这些是范围边界，不是剩余半成品。控制面只负责任务/状态/lease/恢复的可视化与写入。
- M3 定位为**文件模式、人工批准**的评估闭环：不自动生成候选、不定时调度、不做 holdout/依赖安装/多套件；仍不自动合并或发布（D-011）。
- M1 已覆盖本地 JSONL、真实 GitHub 与真实 Gitea 只读同步；Link 分页、私有仓库、限流退避、review comments 等属于后续可选增强，不影响单仓库单用户的日常反馈读取。
- P0-A13 在真实 DSH 0.2.1-rc.2 已满足“至少一个宿主”标准：GUI、真实模型、真实 stop、卸载/重装均通过；DSH 本身不提供 hook 自动注入，已记录为宿主能力边界（手动 `hook` 与 AGENTS 指令路径可用）。Linux 原生浏览器 GUI、多轮长会话/多工作区属于可选补充覆盖，不是发布前置。
- 唯一有意未做的是**发布**：未发 npm 包、未建 GitHub release/tag，等待用户授权。
