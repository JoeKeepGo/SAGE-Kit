## 目标与不变量

用户提供项目规范和一次有边界的授权，Agent 持续交付可验证结果，人员集中处理
目标、重要取舍和最终验收。SAGE-Kit 保留旧版完整治理语义，hook 对抗长任务遗忘，
RSI 从真实开发证据改进方法。减少人员日常介入不等于自行改变授权。

不做 Taluvia 专用流水线、通用任务管理 SaaS、多租户控制平台，也不以“更简单”为由
删除项目需求。先保留功能，再按风险压缩重复文档。没有必要不引入数据库或守护进程。

每个里程碑在现有计划中说明它服务的用户目标、保留的既有能力及任何行为变化。
测试通过不替代此检查；删除/收窄既有能力是产品变更，不能当作内部重构默许。
若实现成果只有任务管理、状态存储或插件模板而未连到治理目标，应记录缺口，
不能以完成底层模块数量宣称完成产品。此检查复用现有计划，不增加逐任务审批。

## 两个循环与一个宿主边界

开发：项目规范 → 有边界的计划/依赖 → 选择已授权任务 → 实现 → 按风险验证 →
项目与风险等级要求的评审及修复 → 保存证据/交接 → 下一已授权任务或人工关口。
Light 工作不默认增加独立评审，检查范围沿用原版验证经济；自动化不能升级治理等级。

RSI：失败/返工/评审证据 → 改进假设 → 隔离候选 → 固定评估与基线对照 →
逐次人工批准或预授权政策判定 → 采用 → 后续效果观察/回滚。RSI 的目标可以是流程、工具、提示或 Skill
候选，不局限于产品代码；不以修改目标/验收/评估资产来获取通过。

自动模式由宿主明确配置，限定具体开发分支和固定计划摘要。政策约定修复判据
（有效基线失败、候选成功），或固定评估器输出的数值指标及最小改进量；不能把
“检查没报错”自行提升为有收益。自动采用后用固定检查复验，失败则恢复本轮原文件；
后续显式观察也可触发回退。目标出现第三方修改、分支/规范/计划偏移或授权失效时
先交接，不盲目重写。每份政策限制轮次，连续两轮无改进或回退则停止。

普通产品开发仍沿已准入任务执行，不要求每次代码修改经过 RSI。完整 docset 的
需求、任务和验收 ID 用于映射；自然语言验收须落到实际检查，不能用文档完整度代替
产品证据。自动 RSI 在项目分支内改进，不自动合并主线、部署或通过最终人工验收。

从零开发也是主路径：初始可以只有 docset，没有代码、依赖清单或工程骨架。
先将选定需求/任务/验收映射到有界计划；宿主模型在准入任务中建立工程、实现功能、
运行固定检查并交接。代码与运行证据是完成依据；生成计划、模板或目录不能代替
产品开发。通用接入步骤与可重现空项目样例见[从文档开发](from-docset.md)。

宿主：由现有 Agent 运行模型、工具与会话；适配器接入真实生命周期与工具调用。
SAGE-Kit 定义治理语义和结果，不另造一个模型执行器。单纯 CLI、模板或事件模拟
不能证明真实宿主接入成功。

## 项目接入与持续授权

项目选择现行规范、计划、验收、权限与状态入口；引用保留原始文档/条目身份。
接入记录只作映射，不复制第二份产品真相。版本变化后检查受影响目标与证据；
冲突不静默取历史版本。文档中的命令不是自动执行授权。

一次执行约定至少包括：目标与已准入工作、允许路径/操作、依赖、预算、完成条件、
下一任务选择、暂停/恢复/失败策略、人工关口。先使用项目现有计划/交接位置，
不要求专用图或全部模板。依赖未满足不推进该任务，但可推进独立已授权工作。
重复无进展按旧版规则进行策略复核与诊断交接，不无限循环。

恢复时以 Git、实际进程、测试和工件刷新事实；明确区分未开始、执行中、结果未知、
已验证和待人工验收。结果未知且可能已有副作用时先核对，不盲重跑。
并行写入使用独立 worktree、明确所有权与单一集成者，不混用状态权威。

## 治理 hook

以下是语义触发点，不是假定所有宿主存在同名事件：

| 节点 | 必须带回的上下文或检查 | 缺失处理 |
|---|---|---|
| 开始/恢复/压缩后 | 当前目标、范围、规范引用、未解问题、下一动作 | 能力未验证时标明，使用显式读取，不声称自动注入 |
| 派发/执行前 | 任务与目标关联、路径/操作权限、子 Agent 继承边界 | 必需授权不明则停止该动作 |
| 工具/验证返回后 | 实际退出码、失败、证据归属、预算与进度 | 不把缺失结果记为成功 |
| 完成/跨阶段前 | 必需测试、评审、验收与准入条件 | 无证据不完成，未授权不跨阶段 |

注入必须有界且不隐藏截断：优先保留权威引用、范围和停止条件，剩余内容可按需
读取；上下文过期时刷新。hook 只读取/记录/判定，模型修复和 RSI 由已授权执行流处理。
提醒不能证明语义理解；机械门禁不能证明操作系统隔离或阻止宿主的所有旁路。

## 最小产品路径与证据

规范 owner 为目标项目；治理定义 owner 为 `docs/` 与随 Skill 打包的相应资源；
执行与会话 owner 为宿主；持久协调结果记录在项目选定的位置，不能覆盖规范真相。
入口为宿主项目指令/Skill、显式工具和已验证生命周期事件。
交付为完整治理 Skill 加可选宿主适配；适配器具体文件/协议在 R1 确定。
证据依次区分静态、fixture、真实组件、打包安装和真实任务结果，不自动升级证明。

## 已准入的实施顺序

| 阶段 | 交付 | 退出条件 |
|---|---|---|
| R0 | 恢复基线、明确决策与验收、历史复用清单 | 原版资源检查通过；重建范围经独立审查；不宣称运行时完成 |
| R1 | 最小执行约定、恢复记录与 hook 语义，项目接入示例 | 原治理无回退；小型项目覆盖连续任务、失败、中断和准入；具体接口先写验收 |
| R2 | DSH 原生插件接入上述流程 | 隔离环境中真实发现/注入/检查/恢复可复现，记录版本和安装工件 |
| R3 | 复用并修复 RSI 组件，接入治理反馈 | 开发证据形成候选、固定评估、人工批准前不可采用、可回滚 |
| R4 | Codex/Claude 适配及跨项目验证 | 每宿主实际支持矩阵；不同结构项目保持同一治理语义 |
| R5 | 可选 GitHub/Gitea Issue 与 Actions 证据读取 | 显式宿主工具读取真实平台；版本/运行/jobs/来源绑定；失败与资源边界；本地证据可进入持续执行及 RSI |
| R6 | 真实模型按文档推进自身项目的首轮试运行 | 三项有界任务、实际失败修复、边界重启续接、准入停止与资源记录；不推导长期可靠性 |
| R7 | 从文档启动空项目；项目分支内预授权自动 RSI，与人工模式并存 | 真实模型从零交付；改进判定、后验/回滚、政策绑定、多轮停止；宿主与安装包验证 |

RSI 从 R1 的证据设计开始参与，R3 是集成里程碑而非可有可无的附加功能。
这些阶段是建设顺序，不意味着授权生产发布、远程写入或付费调用；自动采用 RSI
仅在 R-009 明确的项目政策覆盖内允许。
首轮使用本地夹具；真实宿主已有合法运行条件时继续，不以需要选定实现细节为由
反复请用户批准普通工作。

R5 的规范见[平台证据](forge-evidence.md)。平台 API 拥有观察到的 Issue/运行事实，
本地不可覆盖的快照拥有本次观察；项目规范仍拥有验收与权限。实际入口为 DSH 与
Codex/Claude 的显式工具 → 可选读取模块 → 快照 → 原持续执行/RSI 的本地文件引用。
交付仍为 `adapters/` 可选包；不修改治理核心，也不引入任务状态服务。快照摘要不
证明服务器诚实，成功运行也不证明工作流实际测试了所有声明；调用方需选定正确的
仓库、提交、工作流和必需 jobs，并在相关事实变化或关键关口重新读取。

## 历史成果复用

从归档提交逐项提取并验证，不整批合并旧架构：

- `packages/dsh-plugin/`：复用真实工具和生命周期接入经验；重接治理目标与准入。
- `src/core/runs.ts` / worktree：评估复用恢复与隔离逻辑，不恢复任务管理器主体。
- `src/rsi/`：复用候选/评估/审批；补齐基线保护检查及新治理语义。
- Codex/Claude 宿主模板：只作原型；没有真实会话证据不记支持。
- 控制面/UI：不是首轮交付；不引入已知锁竞争、恢复非原子、错误脱敏问题。
- feedback：未来复用前修复半行写入重试丢失；任何已发现缺陷不能因搬迁被视为关闭。

本轮不修改 Taluvia 文档、不启动其产品开发，也不将其 `PLANNED_NOT_STARTED`
任务状态提升为 SAGE-Kit 的执行证明。
