# 从文档开始开发项目

这是开发主路径，适用于只有文档的新项目，也适用于已有代码的项目。
SAGE-Kit 提供治理与恢复，现有 Agent 宿主负责阅读、实现和运行工具。没有运行中的
宿主或单独授权的调度，就没有后台开发。自动 RSI 改进开发方法，不替代开发任务。

## 一次接入

1. 选定当前 docset 版本、目标和首批任务，保留需求、任务、验收的原始 ID。
   只引用本轮相关规范；冲突先由文档权威解决。Taluvia 的自然语言验收尚不是
   可执行测试，必须落实为项目实际检查，不能把文档检查通过当作产品通过。
2. 在开发分支准备有界 continuation 计划：任务依赖、允许路径和操作、检查 ID、
   风险所需评审、期限/尝试预算及最终人工关口。工程初始化可以就是第一项任务；
   不要求预先有应用代码。网络、依赖安装、外部服务和凭据按项目需要明确授权。
3. 固定验收输入及宿主配置，映射 `projectRoot`、plan/state 和实际工具名。治理、
   验收和评估脚本不列入 RSI 目标；自定义宿主配置必须显式列入 authority。
   在宿主确认工具注册、开始前的拒绝和生命周期提醒。原生工具事件不覆盖的路径
   必须记录，不能把模型指令或 hook 当成文件系统沙箱。
4. 模型依次 inspect → begin → 实现与实际检查 → finish，继续下一已准入任务。
   检查日志保存真实退出码且每次路径独立；失败留下原记录。未知副作用先核对，
   规范改变只使受影响证据失效，不直接篡改状态“恢复通过”。
5. 在最终人工关口交付代码、可运行成果、测试、评审和剩余问题。产品完成、人工
   验收、合并及发布是不同决定；分支自动采用 RSI 不会授予后几项。

若允许自动 RSI，另外选择固定 RSI 计划及摘要、开发分支、修复或数值改进判据、
最多三轮和期限，由可信宿主配置 `rsiAutomaticPolicy`。模型只提交候选；服务执行
同一固定评估、自动采用及后验，已知回退范围内恢复本轮文件。正常产品提交可以在
轮次之间继续；一轮尚未结束时不能把新提交混入旧评估。详见 [RSI](rsi.md)。

## 可复现的空项目样例

[样例](../../examples/rebuild/from-docset/README.md)只有规范、计划、宿主映射和
独立验收器，没有产品代码。模型应开发一个离线任务依赖分析工具：库、命令行、
自有测试及使用文档，依次完成三项任务。固定验收检查实际导出 API、进程输出、
输入错误、依赖判定和输入不变；模型不得修改这些验收资产。

这比单文件 greeting 多了工程和多阶段交付，但仍是小型离线 Node 项目。它不证明
任意大型 docset、全部宿主、部署流程或长期无人工干预都可靠。R7 的真实模型记录
和组件自动 RSI 证据分别归属，不相互冒充，实际结果见[进度](progress.md)。

## R7 本轮验证边界

控制者将样例复制到新的隔离 Git 项目，初始化 `main`，切换 `workflow/docset-demo`；
初始清单没有 `src/`、`bin/`、`tests/`、`package.json` 或产品 README。控制者只准备
规范和固定验收，不提供实现代码。真实 Codex 使用现有 ChatGPT 登录和已验证安装包，
按 R-009 的 20 分钟/80 工具/16MiB 上限工作；实际使用模型和版本写进运行记录。
只允许本地实现、检查与证据，不安装依赖、不访问网络、不 push/发布，不改 Taluvia。
宿主模型连接是运行条件；任务禁止联网不等于操作系统网络隔离。

运行后控制者独立复跑固定验收，核对 authority/安装包摘要及允许路径，再做一次
独立最终评审。保留失败、启动修正和干预记录；未触发的自然压缩或长期观察不称为
已验证。CPU/IO 采样只用于本轮观察，不推导通用低开销保证。
