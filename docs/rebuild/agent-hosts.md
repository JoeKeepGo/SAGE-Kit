# R4：Codex / Claude 可选宿主接入

权威：[决策](../decisions.md)、[SPEC](SPEC.md)、[验收](acceptance.md)。
本文件先约定行为与检查；实际支持程度以[进度](progress.md)的版本和运行证据为准。

## 实现边界

复用 R1 continuation 与 R3 RSI，不复制计划/结果模型。提供由宿主按连接启动的
本地 stdio MCP 适配器；无监听端口、轮询、模型循环、自动安装或默认配置改写。
连接关闭即取消正在执行的操作。原治理 Skill 不依赖该可选进程。

显式配置选择项目绝对路径、计划与状态相对路径、宿主、受检查工具名，以及可选
RSI 计划/状态。一个连接只服务一个项目/执行者；子 Agent 必须独立配置与授权，
不共享写入所有权。配置和入口属于当前可信接线，RSI 不得修改。

`sage_inspect`、`sage_begin`、`sage_finish` 与 DSH 使用同一 API。
`sage_hook` 接收宿主事件，重读有界权威并返回原生提醒/拒绝。成功的新 begin
只在当前连接建立执行标记；重放、错误、恢复或权威变化清除标记。hook 不授予
操作系统权限，不执行任务、不运行 RSI、不把工具返回自动记作测试通过。

关键生命周期刷新完整证据；普通受检查工具事件只读计划/规范/状态，变化后才
刷新完整证据，避免每次扫描历史证明。无变化不写状态；上下文超限明确报错。
Stop 只反馈下一已准入工作或未结结果；不越过人工关口，不制造无限续跑。

RSI 显式工具复用候选/评估/回滚。采用与回滚通过宿主 MCP elicitation 请求具体
差异的一次确认；没有能力、拒绝、取消或失联均不批准。模型参数不能提供批准。
宿主客户端负责将询问送给人；自动答复器只能作为协议测试证据。

## 支持与限制的记录方式

当前官方文档提供 [Codex MCP hooks](https://learn.chatgpt.com/docs/hooks) 与
[Claude hooks](https://code.claude.com/docs/en/hooks)。接口与失败语义必须用实际
安装版本复验。MCP hook 不能把宿主失联或报错升级为批准；宿主可能仍放行其原生
工具，故这不是全面隔离。适配器自身 begin/finish/RSI 检查失败必须返回错误。
安装者仍需保留项目指令及宿主权限配置；缺少提醒时显式调用 `sage_inspect`。

## 本轮验收

- 真实宿主从隔离配置发现已打包的工具，hook 上下文实际到达模型请求。
- 实际 begin/工作/finish 的结果与文件对应；无 begin 拒绝受检查调用，重连后
  先核对未结副作用，不将 replay 当新授权。
- 当前版本能触发的开始、恢复、压缩及完成分别记录，不从模拟事件推断支持。
- 协议覆盖畸形/过大输入、取消、超时、缺少批准和读写边界；恢复不盲重跑。
- CPU、耗时、逻辑读取量与写入计数记录输入规模；空闲不扫描、不产生计数日志。
- 两种结构的项目沿用同一治理语义；Taluvia 仅只读映射，不启动产品任务。

以上均不等于真人策略采用、真实模型长期收益或全部平台验收。
