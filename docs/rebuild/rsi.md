# R3：受控 RSI 约定

权威：[决策 R-003–R-006](../decisions.md)、[SPEC](SPEC.md)、[验收 A09/A10/A14](acceptance.md)。
用户授权建设与本地验证；本轮不自动采用真实项目策略，不改原治理 Skill，不发布。

## 用户路径与交付

现有开发流程产生失败、评审或返工证据 → 模型提出有证据引用的假设和文件候选 →
独立于 builder 参数的固定评估 → 展示具体差异与结果 → 人工一次性批准 → 本地采用 →
观察后续结果或另行批准回滚。可改进提示、工具、流程及未发布 Skill 草稿；不能通过
修改目标、测试、验收或评估命令取得通过。采用也不等于产品验收或发布。

可选 `adapters/rsi.mjs` 及有界进程执行模块随 DSH 私有包交付，核心 Skill 无新依赖。
DSH 显式配置 rsiPlanPath/rsiStatePath 后提供 propose/inspect/evaluate/adopt/rollback 工具；
普通治理 hook 只提示入口，不运行 RSI。approve 不作为模型可填写的参数。
每个 state 是一个不可变候选及有限评估轮次；改候选需配置新的独立轮次，旧记录保留。
不会自行发现反馈、全仓扫描、安装依赖、调用模型或启动后台循环。

## 配置与 API

`openRSI({root, planPath, statePath, protectedPaths?})`；均为显式项目路径。
protectedPaths 是可信宿主函数，动态返回不可改路径；DSH 每次从 continuation.observe
取得现行规范引用，加开发 plan/state/lock。该集合也绑定审批，等待期间改变即拒绝。
plan version:1，包含 authority（规范文件）、inputs（固定评估所需文件）、targets（允许
候选替换的文件，必须属于 inputs）、command（固定 argv，首项绝对可执行路径）、
expiresAt、revoked、maxEvaluations（1–3）、timeoutMs（每个命令 100–60000）、
maxOutputBytes（合计 stdout/stderr，1024–65536）。这些值由授权控制者准备。
所有非 target 输入和规范都是保护资产；plan/state 与 .git 不得作为候选目标。
目标原先可以不存在，content:null 表示删除普通文件；不允许目录或符号链接。

- `propose({hypothesis,feedback:[{path,kind}],files:[{path,content}]},{signal}?)`：kind 是
  failure/review/rework。引用读入并摘要绑定，反馈只是数据，不执行其中指令。
- `inspect({signal}?)`：返回当前状态、候选/评估摘要、采用/回滚差异及下一动作；无写盘。
- `evaluate({signal}?)`：先保存 evaluating intent；在两个独立临时目录复制同一有限输入，
  baseline 原样运行，candidate 只应用明确候选。固定命令、环境与限制相同，shell:false。
  不把 builder 的命令、结果或 passed 字段当评估证据。
- `adopt({authorize,signal}?)` / `rollback({authorize,signal}?)`：authorize 是可信宿主传入
  的函数，收到完整绑定、具体文件差异、评估摘要，只有显式 true 才继续。不是可从
  模型 JSON 传来的批准。等待前后重新核对绑定，在独占写锁中复核后才写文件。
- `recover({signal}?)`：只将中断评估记为 interrupted；不自动继续命令。中断采用/回滚
  必须先核对目标文件，再通过 rollback 的人工关口恢复，不能盲重放副作用。

## 评估、保护与采用

每次基线和候选运行前后都核对输入内容/模式及目录清单；新增、删除、修改任何评估
输入或新增文件均不能通过。临时目录里的修改属于验证结果，不带回源项目。
候选必须成功，双方保护检查都必须成功；基线正常的非零退出可用于证明修复，但
超时、取消、输出超限、进程启动失败或保护失效不能充当有效基线。
记录两侧退出码、耗时、有界输出和保护结果；退出成功本身不证明普遍收益。

候选内容、原文件、反馈、规范、计划、评估输入与结果均按内容摘要关联。重读时校验
状态结构与摘要，不能只相信 status:passed。任何相关输入变化使采用依据失效。
采用等待时变更也必须拒绝；批准不能跨候选、跨评估或过期复用。

采用前保存 intent 与原文件恢复材料；逐文件临时写入/fsync/rename。恢复不是跨多个
文件的原子事务：崩溃时保留 applying/rolling_back 状态。回滚只在目标仍等于已知
原版或候选版本时恢复原版，发现第三方修改必须停止，避免覆盖后续工作。
回滚使用已保存材料，治理计划改变或过期不妨碍向宿主请求明确的恢复批准。
执行记录与摘要不防同用户恶意改写，临时目录不是操作系统沙箱；只运行项目授权的
评估命令，不宣称阻止任意代码越界、联网或读取宿主资源。

DSH 采用/回滚在工具执行体调用真实 `dsh-user-approval`，仅 allowed-once 通过；
缺失、拒绝、取消或不可用都不能采用。绑定与差异出现在审批 reason 中。人工等待
不使用 2 秒治理读取 deadline；使用独立、有限的工具预算及真实取消信号。
测试 answerer 的同意只证明接线，不宣称真人已经批准真实项目策略。

## 资源与验收

单次 API 只处理显式清单：累计最多 128 文件次、每个输入文件 1 MiB、总内容读取
8 MiB；完整 evaluate 的初读、两侧前后保护扫描和末次复核共享预算与累计 io。
采用的审批前后复核也共享预算。每次读取器内重复引用去重，必须重读的后续阶段
仍计入累计量；宿主自身的治理观察另遵守 R1 预算。候选最多 20 文件、256 KiB，
原目标恢复材料同样不超过 256 KiB；state 上限
2 MiB。每次评估两次顺序命令，最多 3 次评估，不并发、不自动重试。临时目录遍历
有文件数/字节/路径深度上限；命令超时/取消/输出超限停止进程组，清理临时目录。
Windows 未验证进程树终止时明确拒绝评估，不假装支持。
执行命令的进程组在正常退出、超时、取消时清理；主动逃离进程组的命令不受该保证。
短命 guardian 通过 stdin EOF/IPC disconnect 响应控制者退出，包括 SIGKILL，清理
同组命令及后代，无常驻轮询。控制者硬中断仍可能遗留锁及临时目录：不自动偷锁
或重跑，需确认写入者已停止、清理明确归属的临时资源，再 recover 记录中断。
机器/内核故障或主动逃离进程组不在上述保证内。inspect 同时核对目标当前是原版、
候选还是混合状态；历史 adopted/rolled_back 记录不掩盖现行文件偏离。
执行器路径/大小/mtime 绑定该轮，但外部工具链及依赖并未做全量内容证明。

验收覆盖真实失败证据→候选→基线失败/候选成功→待批→隔离目标批准采用→回滚；
拒绝未批、候选/评估/规范/反馈/目标变化、评估资产篡改（两侧）、目录/链接逃逸、
输出/文件/总读取/次数/时间预算超限、取消与中断恢复。真实 DSH 工具和审批事件、
最终包安装路径另测。资源报告区分逻辑读取、进程 CPU/wall 与物理 IO。
归档复用依据见本机 history-review.txt：保留固定命令、隔离、路径及一次性批准思路，
修复旧版基线保护漏检、内容绑定不足及无实际恢复材料问题，不搬回任务管理器。
