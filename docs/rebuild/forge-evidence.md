# R5：Git 平台证据

依据[决策 R-007](../decisions.md)。首轮支持 GitHub/Gitea 的指定 Issue 与指定 Actions
run/jobs；PR review、日志全文、工件下载/校验、CD 目标健康与平台状态汇总尚不实现。

配置选定平台 API 地址、仓库、环境变量凭据名和项目内证据目录；模型参数只能选择
配置的来源、对象编号以及此次检查期望的提交、工作流路径和必需 job 名。凭据不进入
参数或回执，HTTP 仅允许显式 loopback 测试端点，其余使用 HTTPS，禁止重定向。

`sage_forge_capture` 是独立的显式工具，不从 hook、inspect、finish 或 RSI 评估中
隐式联网。抓取后保存新的内容寻址 JSON 快照，不覆盖旧观察；返回相对路径和摘要。
快照正文为不可信数据，即使含命令或“批准”也不能改变项目规范。原 `sage_finish`
仍由调用方负责真实检查结论；它只绑定本地证据字节，不把任意 JSON 自动认证为
平台证明。RSI 可将该路径作为 failure/review/rework 反馈，采用仍需原人工批准。

Issue 保留身份、作者、状态、内容和更新时间，结论只能是 FEEDBACK。Actions 读取
指定 run 的当前 attempt 及全部 jobs，然后重读 run 排除观察期间重跑或状态变化。
GitHub 使用 attempt 专属 jobs 端点；Gitea 按实测版本能力处理。只有 run 与全部 jobs
均完成且成功、提交与工作流路径匹配、必需 jobs 全部存在且无歧义，才报告 PASS。
缺失、取消、跳过、进行中、歧义或无法绑定的证据不能通过。失败结果原样保留。

该 PASS 只评价指定运行在观察时的状态，不能称作“当前分支 CI 全绿”。另一 run 的
新失败、提交/工作流/需求变更会影响适用性；关键关口必须选择当前相关证据，不能
用旧 PASS 覆盖当前 FAIL。`head_sha` 原样记录，不推断其一定是 PR merge SHA；它也
不证明工作流内部未 checkout 另一版本。平台状态不等于可信构建或独立人类评审。

每次最多 30 秒、16 HTTP 请求、4 MiB 响应总量、单响应 1 MiB；快照最多 1 MiB，
jobs 最多 500。分页超限、未知形状、身份不一致或 HTTP 错误明确失败，不提交半份
成功快照，不重试、不跟随服务器提供的任意 URL。快照目录不许符号链接，排他写入
及原子发布；无后台轮询、模型调用或默认凭据发现。loopback 测试不是生产安全证明。

验证图：受控 API 反例 → 真实 GitHub/Gitea API → 打包安装后的同一读取模块 →
宿主工具与 continuation/RSI 文件引用。真实宿主模型长期使用、远程 CI 对当前分支
的验证和最终人工验收分别记录，不从本轮读取历史运行推导。
