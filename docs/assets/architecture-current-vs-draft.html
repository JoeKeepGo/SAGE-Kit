当前版本：单宿主深集成 + 文件适配0.2.0-alpha.1 · 已实现
Host layer
宿主 Agent
DSH · Codex · Claude Code；DSH 是当前主开发环境，Codex/Claude 目前只有文件适配。
Activation / adapter layer
当前的三种接入路径
  • 已实现DSH 原生插件 `sage-kit-dsh`：5 个原生任务工具 + `agent/pre-step` 自动 brief；真实 headless E2E 通过。
  • 文件适配Codex / Claude Code：安装 `.agents/skills` / `.claude/skills` + `AGENTS.md` / `CLAUDE.md`；原生插件/hook 未验证。
  • 手动CLI hook：`session.start` / `command.after` / `stop` 协议已实现，但只能由宿主显式调用。
  • 未实现没有宿主 hook 自动安装；`init` 只装 Skill/说明块，不注入 hook。
  • 未实现没有 `off / brief / strict` 模式；没有统一的宿主命令映射。
当前重点：把 DSH 插件做深、把 CLI/Skill做稳；不是多宿主分发。
DSH 插件是可选独立包（0.2.0-alpha.1），不进入核心依赖；核心仍是一个包。
权限边界：插件不复制状态，只调用 CLI/库；控制面可选、loopback、不双写。
草稿：CLI 核心 + 多宿主薄适配器DRAFT · 未实现
Host layer
宿主 Agent
先做 DSH · Codex · Claude Code；其他宿主按真实需求增加，不追 20 个。
Thin adapter layer (proposed)
每宿主一个薄适配器
  • 草案安装 Skill / 受管说明块；幂等、owned 文件、不覆盖用户配置。
  • 草案`SessionStart` / `agent/pre-step` 注入 brief；≤2 KB、≤2 s、无网络/模型。
  • 草案命令/工具只映射 CLI：`sage-task` / `sage-brief` / `sage-doctor`。
  • 草案模式 `off / brief / strict`；默认 brief，strict 只约束标记任务。
  • 草案可选 RSI 门禁：只查 `rsiProposalId` 任务；turn 级、fail-closed。
  • 草案适配器包边界待 ADR；核心仍是一个包、一个权威状态。
草稿的重点：分发/激活，不是重写核心；不自动批准、不自动执行、不做逐工具保证。
参照 ponytail：单一 canonical 规则 + 多宿主薄包装；不复制其提示词/品牌/statusline。
共同核心：当前与草稿都保留同一份 CLI + Skill + 状态
草稿不复制核心、不新增第二状态源；适配器只能调用 CLI/库。当前核心能力已实现，草稿只改“接入层”。
01 · Canonical skill
skills/sage-kit/SKILL.md
唯一规则源：任务、验收、证据、停止条件。
  • 无状态、无数据库、无守护进程
  • Codex/Claude/DSH 共用同一份规则
  • `AGENTS.md` 仅作压缩 fallback
02 · CLI core
sage-kit CLI
确定性操作；所有宿主共用。
  • init / doctor / task / worktree / run
  • brief / hook / feedback / control / rsi
  • uninstall / version · Node ≥22
03 · Authoritative state
.sage-kit/
文件模式默认；唯一的任务/证据写入源。
  • tasks / runs / events / worktrees
  • brief / rsi / config
  • 文件模式与控制面模式不双写
04 · Optional / governance
控制面 + 反馈 + RSI
可选本地控制面；人工批准，不自动发布。
  • loopback HTTP/SSE/UI + SQLite WAL
  • GitHub/Gitea 只读反馈（M1）
  • RSI：create → evaluate → approve（M3）
  • 扩展接口：TaskSource / FeedbackSource / EventSink / Bundle
共同边界：单用户 / 本地 / 单仓库；核心 CLI 零运行时依赖；不引入多租户、远程 API、通用插件市场、自动合并/发布。
状态矩阵：把“已实现、部分验证、草稿”分开
颜色对应图例；未执行项按 D-018 保持 `NOT_EXECUTED` / `NOT_IMPLEMENTED`，不写成“支持”。

已实现 / 已验证

  • CLI + Skill + `.sage-kit/` 文件状态；`npm test` 206 项，205 通过、1 跳过。
  • DSH 原生插件：5 个工具 + `agent/pre-step` brief；headless E2E PASS。
  • 本地控制面：loopback HTTP/SSE/UI + SQLite WAL；无远程访问。
  • M1 反馈只读（GitHub/Gitea）；M3 RSI 手工评估 + 人工审批。
  • 文件适配器：DSH / Codex / Claude Code 安装 Skill + 说明块。

部分 / 未验证

  • DSH Web GUI、配置分支、故障降级：NOT_EXECUTED。
  • Codex / Claude 原生插件与 hook：NOT_VERIFIED。
  • 宿主 hook 自动安装：NOT_IMPLEMENTED；`init` 不装 hook。
  • Windows/macOS 上的 DSH 插件运行：NOT_EXECUTED。
  • RSI 自动批准/合并/发布：设计上不实现（L2 上限、人工批准）。

草稿 / 未实现

  • Codex / Claude Code 薄插件与 `SessionStart` 激活。
  • `off / brief / strict` 模式与宿主命令映射。
  • Task.rsiProposalId + `checkRsiGate`：只约束标记任务。
  • RSI 门禁的 turn 级 reject；没有 pre-tool 拦截。
  • 适配器包边界、发布包装、安装矩阵：待 ADR / 待实现。
