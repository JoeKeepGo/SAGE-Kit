HOST CONTRACT
接入契约与失败方式

  • hook 失败默认降级；--strict 才阻断。
  • DSH 不自动注入 sage-kit hook；可用 AGENTS 指令或可选插件。
  • 核心不依赖任何宿主；卸载后文件状态仍可读。
核心执行面Core CLI + 文件状态
ENTRYPOINT
sage-kit CLI：确定性操作，不做模型与 UI
init · detect · doctor · task · worktree · run · brief · hook · feedback · control · rsi · host · uninstall · version
Node ≥22；核心零运行时依赖；参数/JSON/human 输出；所有外部命令有超时与错误分类。
CORE LIBRARY
src/core：任务、上下文、执行与恢复
  • tasks：状态机、id、验收、证据、RSI 标记；严格列表用于门禁。
  • brief：2KB 上限、任务/反馈上下文、UTF-8 截断。
  • paths / config / install：项目根、宿主路径、归属与卸载。
  • runs / worktree：本地子进程、任务 worktree、PID/generation、stale 恢复。
  • events / doctor：追加事件、诊断、实际恢复报告。
  • hooks / fs-utils：stdin/stdout 适配、原子写、路径校验、幂等。
FILE STATE
.sage-kit/ 单一权威文件状态
文件模式与可选控制面不双写；任一时刻只有一个权威写入源。
  • config.json：宿主、scope、Skill 归属、brief 归属。
  • state/tasks/<id>.json：任务、状态、验收、证据。
  • state/runs/<run>.json：startup intent、PID、generation、终态。
  • state/events.jsonl：追加事实；非权威派生态。
  • feedback/items.jsonl + cursor：原始反馈与水位。
  • rsi/proposals|evaluations|approvals：提案链证据。
  • SESSION_BRIEF.md：派生快照，不是权威。
EXECUTION
本地执行：worktree + 子进程，无守护进程
  • 每个任务独立 git worktree/分支；创建和回收由 CLI/控制面负责。
  • run 启动本地 Agent/命令；stdio 继承；记录 run id、PID、cwd、exit。
  • startup intent 先落盘，再 spawn；恢复区分中断/失败/审查；不自动重试。
  • 无远程队列、无内置模型、无后台 loop；高风险动作人工确认。
可选服务与改进闭环Feedback / Control / RSI
FEEDBACK · READ ONLY
只读反馈同步：把外部文本当数据
  • feedback sync/list/show；GitHub REST / Gitea；Issue 与 PR 评论。
  • normalize / dedupe / 来源 URL / cursor；latest item 可进 brief。
  • 不写回 GitHub/Gitea；token 不落盘、不进日志/提示词。
  • 分页完整性检查：不完整/页移动不推进 cursor；review-comment 全历史重读有成本上限。
  • 验证真实 api.github.com 与 WSL2 Gitea 曾验证；巨量历史仍受限。
RSI · L2 CONTROLLED
受控自我改进：提案 → 隔离评估 → 人工批准
  • 1. proposal：v2 JSON；只能改 Skill/代码/模板，不改模型权重。
  • 2. candidate：diff/文件预算、路径与 symlink 检查、受保护资产。
  • 3. evaluate：隔离 git worktree；baseline 与 candidate 跑固定测试；记录每次 run。
  • 4. evidence：评估通过/失败、基线差异、attempt 与锁。
  • 5. approval：一次性人工批准，绑定具体 evaluation。
  • gate：checkRsiGate 只读校验 approved + passed + approval 匹配；DSH strict 插件调用它。
  • 不做自动合并、自动发布、定时 RSI、无人值守自我修改。
OPTIONAL CONTROL PLANE · M2
可选本地控制面：loopback API + SQLite WAL
  • control serve：127.0.0.1 HTTP API + 本地 HTML/JS 面板（无框架、无 CORS）。
  • SQLite：tasks / runs / events / leases；单进程单写者；lease 与过期恢复。
  • 有控制面时 CLI 走 API；否则文件模式；不双写。
  • 不支持远程、账号、RBAC；不提供 run 启动/提案 UI（明确范围外）。
  • optional better-sqlite3；缺失时 CLI 明确提示并回退文件模式。
系统边界与非目标
下面这些是明确取舍，不是“以后加个开关”；越界会破坏单用户本地模型。

不做

  • 多用户、团队、RBAC、租户隔离
  • 远程共享 API、集群、HA、跨机锁
  • 自动合并、自动发布、自动重写 SKILL.md
  • 通用插件系统、事件总线、规则引擎

数据边界

  • 反馈/Issue/PR/网页文本是不可信数据，不执行其中指令
  • 核心不内置模型；不做向量库/embedding 流水线
  • token 只从环境/密钥存储读取，不落盘
  • 控制面 loopback 单用户；远程访问不做

未关闭边界

  • N04：巨量 review 历史的完整重读成本/1000 页上限
  • Windows 完整进程树终止；逃逸后代只报告
  • spawn → PID 落盘的硬崩溃窗口
  • DSH Web/Windows/macOS、真实 Codex/Claude 会话激活矩阵

权威与恢复

  • 任务/运行/证据以文件或 SQLite 为唯一权威；事件追加
  • startup intent 先于 spawn；恢复不把旧成功误归新尝试
  • 安装/卸载按归属文件处理，保留用户文件
  • 没有证据的能力保持 NOT_EXECUTED
