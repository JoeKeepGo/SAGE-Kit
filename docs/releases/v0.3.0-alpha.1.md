# SAGE-Kit v0.3.0-alpha.1

This alpha combines the original governance Skill with optional document-driven
development, host hooks and bounded RSI. The governance component remains
**v2026.8.13.1**; the source release and optional adapter are **v0.3.0-alpha.1**
and **0.3.0-alpha.1** respectively. This is a GitHub prerelease, not a stable
release or an npm publication.

## What is included

- The complete original governance core, preserving project authority,
  evidence ownership, risk-based review and human acceptance.
- Document-to-task mapping and an empty-implementation example for starting a
  project from documents, plus bounded continuation and recovery records.
- Optional DSH, Codex and Claude Code integration. Codex shell/patch event names
  are normalized, and caught pre-tool errors now return a denial the tested
  native host accepts. Direct and code-mode nested calls have side-effect tests.
- Human-approved RSI and an opt-in mode for automatic adoption, postchecks and
  rollback within an explicitly authorized project development branch. The
  model cannot grant its own authority or alter the fixed evaluation assets.
  The MCP proposal tool publishes its complete evidence/file object structure
  and distinguishes proposal storage from adoption.
- Optional, bounded GitHub/Gitea Issue and Actions evidence reads. Issue contents
  do not grant authority; a successful workflow does not prove deployment.

There is no SAGE-Kit task CLI, polling daemon, database service or separate model
executor. Hooks reuse the host connection and do not call a model or the network.

## Validation and limits

The frozen, offline-installed adapter passed the full local suite: **277 passed,
zero failed, one Windows-only case skipped**. Focused Codex native Hook tests
passed **15/15**, including direct/nested denial before begin, valid execution,
replay/reconnect, expiry and missing-authority errors. The prior package's
error-denial failure was reproduced and retained as a counterexample.

A real `gpt-6.1-sol` trial on the same installed artifact built Task Lens from no
product implementation, passed fixed acceptance and 35 product tests, resumed
the same session at a completed task boundary, and completed automatic RSI
adoption, observation, rollback and re-adoption before stopping at the human
gate. The model repaired a transparently seeded method defect and applied the
repair to seven real development records. Re-adoption demonstrates recovery,
not a second independent improvement.

The first candidate failed because its RSI proposal contract lacked object
details; diagnostic searches extended outside the trial project and the
controller stopped it. That failure remains recorded. After correcting the
public contract, the controller fixed the test harness's stop handling and made
the diagnostic scope reminder explicit. The corrected run used a fresh empty
project and the same fixed product/evaluation inputs, with no supplied product
or candidate implementation. Both runs together used **797.48 seconds, 82
completed tool items and 522,970 captured output bytes**, within the original
budget. Temporary credentials and owned processes were cleaned up.

Tested native versions are Codex CLI **0.163.0-alpha.11.2**, Claude Code
**2.1.310** and DSH **0.2.1-rc.2**. Native regression tests use deterministic local
model responses; actual model development evidence is recorded separately in
the [progress record](../rebuild/progress.md).
CI covers adapter tests, installed DSH integration and static/package checks on
Linux, Windows and macOS; it does not establish native-host support on all three.

Hooks cover the tested events and configuration. Missing/disabled events,
transport failures, hosted/specialized tools and subsequent effects of an
already running process remain outside that evidence. Hooks are not OS
isolation. Long-term resource behavior, natural real-model compaction,
large-project unattended delivery and sustained RSI benefits remain unverified.
DSH/Claude real-model development is not claimed. A project's final acceptance
remains a human decision.

## Install and migrate

Use the tagged source archive for the complete `skills/sage-kit/` directory,
documentation and examples. Governance-only use needs no Node.js runtime. For
optional execution support, use Node.js 22+ and the attached private adapter
package, following the [adapter guide](../../adapters/README.md).

Attached adapter: `sage-kit-dsh-plugin-0.3.0-alpha.1.tgz`.
Verify it with the attached `SHA256SUMS` before installation:

```text
a49ae8587e18e01859e8078de1d7f4d2a67e7dffa1025fe7d1967e69a1cd5726  sage-kit-dsh-plugin-0.3.0-alpha.1.tgz
```

The adapter archive contains 12 payload files, verified byte-for-byte against
source and a fresh offline installation with lifecycle scripts disabled. It
does not include the Skill or examples.

The earlier **v0.2.0-alpha.1** belongs to the archived CLI/database architecture.
There is no automatic conversion of its runtime state. Follow the
[migration guide](../MIGRATION_MODEL_NATIVE.md); preserve old state/configuration
until your project checks the replacement. Existing releases and tags remain
unchanged. Package rollback and rollback of project changes are separate actions.

See the [release procedure](../RELEASE.md) for the fixed artifact, main/tag CI and
post-publication checksum requirements.
