# SAGE-Kit v0.3.0-alpha.3

This prerelease fixes the optional DSH adapter's persistent
`已安装，重启后生效` state. The adapter package is now inserted as a plain
bundle entry: the DSH market can hot-mount it, and a restart no longer leaves
the card reporting an activation that cannot happen.

## What changed

- `@sage-kit/dsh-plugin` is **0.3.0-alpha.3**.
- `adapters/cordis.patch.yml` is a plain insert. It no longer contains
  `disabled: true`, which the DSH market cannot hot-mount and therefore kept
  classifying as “restart required”.
- The plugin's project mapping is optional at load time. A bare install loads
  as a no-op; it starts registering governance tools after the profile supplies
  `projectRoot`, `planPath` and `statePath`. Supplying part of a mapping without
  `projectRoot` fails with `E_CONFIG` instead of silently doing nothing.
- README installation steps now describe the enabled-but-inert default and the
  explicit profile mapping.

No Skill, governance protocol, RSI, hook or task semantics changed. Existing
`0.3.0-alpha.1` artifacts are unchanged and remain immutable.

## Validation

`node --check adapters/dsh.mjs` passes. A local probe confirms the patch parses
as one plain insert row and that `apply()` with default (empty) configuration
registers nothing and does not throw. The packed artifact contains the declared
12 files and its SHA-256 is recorded with the release asset.

The full installed-DSH profile test was attempted on this Windows host; it
booted the explicitly configured fixture profile but failed its RSI policy
assertion, so this prerelease does not claim a full profile acceptance pass.
Do not treat this as a stable or npm release. The governance Skill remains
`v2026.8.13.1`.
