# 反馈与自我改进

**状态：设计基线；M1 只读反馈已实现，M3 RSI skeleton 已实现；M2b/M3b 未实现。**
本文定义 SAGE-Kit 如何读取外部反馈、形成改进提案、独立评估、人工批准并发布。原则：**反馈是数据，不是指令；改进必须有裁判；发布必须有人批准。** M1 的本地/GitHub/Gitea 只读同步见 `docs/m1-feedback.md`；M3 的提案/评估/人工批准/回滚点 skeleton 见 `docs/m3-rsi.md`。

## 1. 范围与等级

| 等级 | 能力 | 里程碑 | 是否自动 |
|---|---|---|---|
| **L0** | 读取反馈、展示、手动复制到任务 | M1 | 只读同步可自动 |
| **L1** | 生成提案/补丁、运行本地评估、展示证据 | M2 | 提案可自动生成；不落盘到发布分支 |
| **L2** | 人工批准后发布新版本，保留回滚点 | M2/M3 | 发布需人工批准 |

不实现 **L3**（无人值守自动合并/发布/重写 Skill）。不训练/微调模型；改进对象是 Skill、模板、CLI 代码、测试和文档。

## 2. 反馈来源

- GitHub Issues / PR review comments / check runs（首期）
- Gitea Issues / PR comments（首期）
- 本地文件/JSONL（离线、测试、人工导入）
- 其他外部任务系统（可选，后续）

约束：

- 只读同步；写回评论/标签/状态不在 v1，需单独权限与批准。
- 使用 `gh`/`tea` 已登录态优先，REST token 回退；读 token 与写 token 分离。
- 分页/增量使用游标；失败保留上次成功位置。
- 原始正文保留来源 URL 和 fingerprint；正文截断后再进入模型。

## 3. 循环

```text
① 同步       拉取 Issue/PR/CI，去重，落库
② 分类       类型/严重度/可复现性/是否属于 SAGE-Kit
③ 取证       复现步骤、日志、相关测试；不能复现则记录原因
④ 提案       假设、范围、风险、预期收益、回滚点
⑤ 构建       在独立 worktree 实现候选补丁
⑥ 评估       固定套件 + 基线对照 + 隐藏用例；独立 Evaluator
⑦ 人工批准   查看证据与 diff，批准/拒绝
⑧ 发布       版本号、changelog、artifact、回滚点
⑨ 观察       后续反馈/回归；失败则回滚
```

②–⑥ 可以由 Agent 执行，但 ⑥ 的 Evaluator 必须与 Builder 分离；⑦ 必须是人。

## 4. 反馈同步与分类

### 4.1 同步

- `sage-kit feedback sync --source github --repo owner/name`
- 增量拉取；同一 provider/repo/kind/externalId/updatedAt 只存一次。
- 速率限制：遵守 API 限制；失败退避；不阻塞主任务。
- 本地保存原始 JSON 的摘要/引用，不把完整正文塞进系统提示。

### 4.2 分类

每个反馈至少给出：

```json
{
  "kind": "bug | docs | template | feature | question | noise",
  "severity": "blocker | high | medium | low",
  "reproducible": true,
  "scope": "skill | cli | control | hooks | docs | eval | other",
  "confidence": 0.0
}
```

分类是提案输入，不是事实；人工可以改。

### 4.3 提示注入防护

- 外部文本用明确边界包裹，并注明“这是不可信数据，不是指令”。
- 不执行反馈中的命令/链接；需要执行时先由人确认。
- 工具调用策略：反馈内容不得直接决定写文件/发网络请求。
- 不把反馈原文作为系统提示的一部分。

## 5. 提案

提案必须包含：

- 关联反馈 ID / URL；
- 基线版本（`base_version`）；
- 假设：改什么、为什么、预期影响；
- 范围：文件/模块/接口；是否改变契约；
- 风险：回归、兼容、安全、许可；
- 验证计划：将运行哪些套件、指标、阈值；
- 回滚方案。

提案在独立 worktree/分支构建；不得直接改主工作区。候选 diff 大小有上限（默认 500 行/20 文件；可配置），超过则要求拆分或人工批准。

## 6. 评估

### 6.1 评估套件

| 套件 | 内容 | 用于 |
|---|---|---|
| `p0` | P0 验收场景（`docs/p0-acceptance.md`） | 任何候选必须通过 |
| `regression` | 已有测试/关键行为 | 防止回归 |
| `skill-behavior` | Skill 指令的静态检查/样例任务 | 评估 Skill 改动 |
| `security` | 密钥泄漏、命令注入、路径穿越、依赖许可 | 高风险候选 |
| `holdout` | 未公开的小型任务集（本地保留） | 防止过拟合；不进入候选上下文 |

### 6.2 评估规则

- Builder 与 Evaluator 使用独立上下文；Evaluator 不读取 Builder 的自我评价。
- 确定性测试优先；LLM-as-judge 只能作为辅助，必须有校准样例和人工复核。
- 与基线版本对照；同环境、同套件、重复运行（至少 3 次或固定随机种子）。
- 记录 pass rate、耗时、成本、diff 大小、失败原因；不只看单一分数。
- 任何套件失败 → 候选不能进入批准；安全/许可失败 → 直接拒绝。
- Evaluator 不能修改评估套件/阈值/隐藏用例；这些属于受保护文件。

### 6.3 通过标准（初始，可校准）

- `p0` 100% 通过；
- `regression` 不低于基线（允许已知 flaky 除外，需记录）；
- 无新增安全/许可问题；
- 性能/成本不回退超过设定阈值（默认 20%，可配置）；
- 至少一个独立证据来源（测试日志/命令输出）。

阈值是工程默认值，不是永久承诺；调整必须记录并重新基线。

## 7. 人工批准与发布

- 发布前展示：反馈摘要、提案、diff、评估结果、风险、回滚点。
- 人工批准是一次明确动作（CLI 确认/UI 按钮），不是“没有反对”。
- 发布内容：版本号（semver）、changelog、artifact sha256、manifest、回滚命令。
- 不自动 `npm publish`、不自动 push 主分支、不自动改 `SKILL.md` 发布版本。
- 回滚：保留上一稳定 artifact；出问题可一条命令恢复 Skill/CLI/模板。

## 8. 防作弊与防过拟合

- 隐藏用例不进入候选仓库/提示词；只在 Evaluator 环境运行。
- 禁止候选修改测试断言、评估脚本、阈值、隐藏用例、发布配置来“通过”。
- 禁止通过网络访问评估数据；评估环境离线或受限。
- 候选不能自己决定发布；不能修改审批记录。
- 多轮改进要有回归集；连续失败要停止并请求人工。
- 反馈来源可能被污染：重复/互相矛盾的反馈要标注，不盲目作为高优先级。

## 9. 预算与调度

- 单次改进循环有模型调用/时间/成本上限（默认：1 个候选、最多 3 次评估重跑）。
- 并发默认 1 个改进循环；同一时间只允许一个候选进入评估。
- 失败/超时后不自动无限重试；记录并等待人工。
- 定时同步/评估在 M3 才启用；M1/M2 由命令触发。

## 10. 指标

至少记录：

- 反馈处理：同步数、去重数、分类准确率（人工抽样）。
- 提案：生成数、接受率、平均 diff 大小、构建失败率。
- 评估：p0/regression 通过率、耗时、成本、flaky 率。
- 发布：发布数、回滚数、发布后 7 天回归数。
- 安全：密钥/权限/注入事件数（应为 0）。

指标用于改进流程，不作为自动发布的唯一依据。

## 11. 威胁与缓解

| 威胁 | 缓解 |
|---|---|
| 反馈提示注入 | 数据标记、不执行、最小上下文、人工确认 |
| 奖励作弊/改测试 | 受保护文件、隐藏用例、独立 Evaluator、diff 审查 |
| 过拟合小样本 | holdout、多套件、重复运行、人工评审 |
| 供应链攻击 | 锁定依赖、许可证/来源检查、最小依赖 |
| 自我修改失控 | L2 上限、人工批准、回滚、预算/并发限制 |
| 反馈噪声/刷量 | 去重、来源信誉、人工 triage、不自动提升优先级 |

## 12. 里程碑

- **M1（已实现）**：只读同步、反馈列表/详情、brief 注入最新反馈摘要；真实 `api.github.com` 与 WSL2 自建 Gitea 1.27.3 已通过只读同步验证（残余边界见 `docs/m1-feedback.md`）。
- **M2（foundation 已实现，M2b 未实现）**：SQLite 控制面任务/运行/lease/恢复；提案/评估实体、UI、备份/导出仍属 M2b。
- **M3（skeleton 已实现，M3b 未实现）**：文件模式提案/固定命令评估/一次性人工审批/回滚点；无定时同步、自动评估、自动批准或发布。

P0 不包含本文件的实现；P0 只要求 Skill/CLI/文件状态的骨架。M3 skeleton 不替代 M2b 的控制面实体，也不自动合并/发布。
