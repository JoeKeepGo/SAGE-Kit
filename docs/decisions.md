依据：用户明确要求保留原版治理、增加持续开发与 RSI，保留 DSH 插件及其他
Agent 的治理 hook，并授权回档后开始工作。

基线为 `v2026.8.13.1`（`6355ecebadba149ceea8d51c446e023eac05a4dd`）。
保留 SPEC 权威、治理分级、规划深度、依赖与派发、权限分离、独立评审、
证据归属、验证经济、续接与人工验收。任务状态或数据库不能替代这些能力。

运行时实验保存于 `workflow/archive-runtime-20261026`
（`69db3da7e8752c7edbedcaac4adceeace527a905`）；它的文档、测试与宿主证据
是历史材料，不自动成为重建版本的权威或当前证明。主分支不改写、不强推。

## R-002：通用框架，项目规范驱动

Taluvia.Space Docset 1.12.0 是复杂参考案例，不是唯一目标、安装依赖或默认任务。
通过项目显式选择的规范入口及引用映射支持不同目录、规模、技术栈。
无需把 556 条需求全部导入才能开始一个已授权任务；不强制每个项目采用相同模板。
框架本地单用户的实现边界，不限制被开发产品是否多用户或分布式。

## R-003：持续执行、hook、RSI 同时保留

治理文本保持无状态。可选宿主适配及最小本地执行支持承载提醒、机械检查、
可恢复进度与评估；不重建宿主模型循环，不默认增加常驻服务、控制台或通用插件平台。

这细化旧基线“无运行时”的范围：治理使用不依赖额外运行时；新增可选执行支持
是用户已授权的建设范围。旧基线中禁止任何框架运行时的绝对表述，不应阻止
该可选层的建设。实际引入代码前必须同步更新受影响的规范、Skill 打包与检查规则，
保留对核心强制依赖及隐藏调用的约束，不能通过删除检查来掩盖冲突。

hook 是长期治理的一等机制，负责关键节点重新装载目标与检查条件；不是只写模板。
RSI 是一等能力，用于改进开发方法，不以“价值尚未证明”为由延期。
开发执行与 RSI 分离状态和权限，不能通过 RSI 自动改目标、放宽验收或给自己授权。

## R-004：有边界的连续自主

一次授权可以覆盖一组里程碑、路径、操作、成本/时间预算与停止条件。
条件满足后继续下一项已授权工作，不逐任务要求“继续”。
可自动实现、测试、评审、修复、交接与选择独立工作；不可推定新范围、生产访问、
付费权限、破坏性操作、合并或发布授权。没有运行中的宿主或已授权调度机制时，
只能持久化交接，不宣称后台持续运行。

## R-005：可验证的宿主差异与保护边界

DSH 插件优先形成实际闭环；Codex/Claude Code 接入同一语义，但按实际版本能力
记录 supported/unsupported/unverified，不虚构通用 hook 事件。
提醒失败可降级并报告；依赖必需门禁的动作在检查缺失/失败时不得宣称已获准。
hook 本身轻量、无模型/网络调用，不在 hook 内直接启动 RSI。

不可信反馈只作为数据；密钥不进入上下文、记录或示例。RSI 候选隔离、保护评估
资产，独立评估后由人批准采用，保留回滚；不自动重写已发布 Skill、不自动发布。
检查通过、实现完成、人类验收和发布授权始终分离。

## R-006：资源开销是验收要求

依据：用户反馈历史有状态 CLI 在实际开发中反复占满 CPU/IO，要求本轮避免重现。
这不是要求取消恢复记录或治理检查，而是避免用频繁启动进程、全仓扫描及重复计算
来实现治理。默认无常驻轮询、无每条工具调用启动 CLI、无后台 RSI 自旋；宿主内
复用模块，按治理事件触发。RSI 单独受预算约束，不进入同步 hook 的关键路径。

本地适配器每次调用必须限制总读取字节/文件数，单次重复引用去重，幂等重放不重写
未变的状态。超预算给出明确资源错误，不截断关键规则、不跳过验证并返回通过。
保留必要恢复记录；只读检查不得因计数/日志而持续写盘。测试验证这些机械边界，
测量报告记录输入规模、环境、耗时、进程 CPU 和逻辑读量；不把小样本结果宣称为
所有项目的低负载保证。真实宿主 hook 和 RSI 长任务资源验收仍是交付门。
