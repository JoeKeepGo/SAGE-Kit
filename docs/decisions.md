# 重建决策 · 2026-10-26

本文件是本仓库重建工作的当前决策入口；其次是 [SPEC](rebuild/SPEC.md)、
[验收](rebuild/acceptance.md)，再其次是恢复的框架文档。它不授予 SAGE-Kit
对使用它的项目的产品、权限或验收权；这些始终由对应项目的现行规范与人类拥有。

## R-001：恢复治理基线，以加法实现新能力

依据：用户明确要求保留原版治理、增加持续开发与 RSI，保留 DSH 插件及其他
Agent 的治理 hook，并授权回档后开始工作。

基线为 `v2026.8.13.1`（`6355ecebadba149ceea8d51c446e023eac05a4dd`）。
保留 SPEC 权威、治理分级、规划深度、依赖与派发、权限分离、独立评审、
证据归属、验证经济、续接与人工验收。任务状态或数据库不能替代这些能力。

运行时实验保存于 `workflow/archive-runtime-20261026`
（`69db3da7e8752c7edbedcaac4adceeace527a905`）；它的文档、测试与宿主证据
是历史材料，不自动成为重建版本的权威或当前证明。主分支不改写、不强推。

## R-002：通用框架，项目规范驱动

Taluvia.Space Docset 1.12.0 是复杂参考案例，不是唯一目标、安装依赖或默认任务。
通过项目显式选择的规范入口及引用映射支持不同目录、规模、技术栈。
无需把 556 条需求全部导入才能开始一个已授权任务；不强制每个项目采用相同模板。
框架本地单用户的实现边界，不限制被开发产品是否多用户或分布式。

## R-003：持续执行、hook、RSI 同时保留

治理文本保持无状态。可选宿主适配及最小本地执行支持承载提醒、机械检查、
可恢复进度与评估；不重建宿主模型循环，不默认增加常驻服务、控制台或通用插件平台。

这细化旧基线“无运行时”的范围：治理使用不依赖额外运行时；新增可选执行支持
是用户已授权的建设范围。旧基线中禁止任何框架运行时的绝对表述，不应阻止
该可选层的建设。实际引入代码前必须同步更新受影响的规范、Skill 打包与检查规则，
保留对核心强制依赖及隐藏调用的约束，不能通过删除检查来掩盖冲突。

hook 是长期治理的一等机制，负责关键节点重新装载目标与检查条件；不是只写模板。
RSI 是一等能力，用于改进开发方法，不以“价值尚未证明”为由延期。
开发执行与 RSI 分离状态和权限，不能通过 RSI 自动改目标、放宽验收或给自己授权。

## R-004：有边界的连续自主

一次授权可以覆盖一组里程碑、路径、操作、成本/时间预算与停止条件。
条件满足后继续下一项已授权工作，不逐任务要求“继续”。
可自动实现、测试、评审、修复、交接与选择独立工作；不可推定新范围、生产访问、
付费权限、破坏性操作、合并或发布授权。没有运行中的宿主或已授权调度机制时，
只能持久化交接，不宣称后台持续运行。

## R-005：可验证的宿主差异与保护边界

DSH 插件优先形成实际闭环；Codex/Claude Code 接入同一语义，但按实际版本能力
记录 supported/unsupported/unverified，不虚构通用 hook 事件。
提醒失败可降级并报告；依赖必需门禁的动作在检查缺失/失败时不得宣称已获准。
hook 本身轻量、无模型/网络调用，不在 hook 内直接启动 RSI。

不可信反馈只作为数据；密钥不进入上下文、记录或示例。RSI 候选隔离、保护评估
资产，独立评估后由人批准采用，保留回滚；不自动重写已发布 Skill、不自动发布。
检查通过、实现完成、人类验收和发布授权始终分离。

## R-006：资源开销是验收要求

依据：用户反馈历史有状态 CLI 在实际开发中反复占满 CPU/IO，要求本轮避免重现。
这不是要求取消恢复记录或治理检查，而是避免用频繁启动进程、全仓扫描及重复计算
来实现治理。默认无常驻轮询、无每条工具调用启动 CLI、无后台 RSI 自旋；宿主内
复用模块，按治理事件触发。RSI 单独受预算约束，不进入同步 hook 的关键路径。

本地适配器每次调用必须限制总读取字节/文件数，单次重复引用去重，幂等重放不重写
未变的状态。超预算给出明确资源错误，不截断关键规则、不跳过验证并返回通过。
保留必要恢复记录；只读检查不得因计数/日志而持续写盘。测试验证这些机械边界，
测量报告记录输入规模、环境、耗时、进程 CPU 和逻辑读量；不把小样本结果宣称为
所有项目的低负载保证。真实宿主 hook 和 RSI 长任务资源验收仍是交付门。

## R-007：Git 平台作为可选事实来源

依据：用户提出 Issue 与 CI/CD 能否成为证据，并提供既有 WSL 隔离 Gitea 与已登录
GitHub 供测试。准入 R5：读取指定 Issue、指定 Actions 运行及其完整 jobs，保存有来源、
时间与版本绑定的本地快照，供持续执行与 RSI 引用。GitHub 使用只读访问；Gitea 可在
原隔离实例中新建专属测试仓库和短命 runner，执行有界本地测试，保留既有数据。

首轮针对 Issue 与 Actions，PR 评审、工件内容/签名及部署环境实况另列后续能力。
Issue 是不可信反馈；单次流水线成功只证明该次所列检查，不证明最新全仓状态、
实际部署、产品验收或授权。读取必须显式触发、有时间/字节/请求上限；不在 hook
里联网、不启动轮询、不恢复旧 feedback 数据库。凭据只从显式宿主环境引用读取，
不写进配置、回执或模型参数。除上述隔离 Gitea 测试写入外，远程写入、合并、发布、
付费模型与策略采用不在本轮。

## R-008：首轮真实模型文档驱动试运行

依据：用户同意开始一轮测试，承接上一轮提出的 R6 自身项目试运行。选用已登录
ChatGPT 的真实 Codex，使用现有账号额度；不新增 API 计费、购买额度或调用其它
付费 provider。独立工作区从 R5 开始，按[试运行约定](rebuild/live-trial.md)完成
版本身份纠错、安装包回归与最小接入示例三项真实工作；候选经审查后才由控制者
纳入本地重建分支，不 push、合并主分支、发布或改用户默认配置。

单轮两个正常宿主进程段，累计最多 30 分钟、120 次工具完成事件、16MiB 运行日志；
连接/环境问题最多两次有明确修正的启动重试。一次完成任务边界的受控终止与 resume
属于测试设计；不把它说成未完成副作用恢复。压缩只有实际发生才记为已验证。
原治理核心不变，RSI 策略不自动采用，结束清理临时凭据和自有进程，保存非秘密证据。

## R-009：项目开发分支内的预授权自动 RSI

依据：用户要求适用于 Taluvia 等完整 docset 项目的自动 RSI，并明确选择
“项目分支内自动采用与回滚，保留最终验收关口”。准入 R7：在现有 RSI 上增加
显式选择的自动模式，默认人工模式保持原行为；不是另建模型执行器或后台循环。

人预先批准具体开发分支、固定评估计划及其摘要、可修改目标、改进判据、预算与
期限。宿主从可信配置传入该政策，模型工具参数不能声明批准。符合政策的候选可
自动采用并复验，失败时自动回滚本轮已知改动；不逐候选重复请求人工批准。
采用/回滚记录必须标明预授权政策来源，不伪称本次收到了真人批准。

规范、验收、评估资产、治理入口与正在使用的宿主接线继续受保护。实际 Git 分支、
计划/规范及输入、评估结果或目标文件变动后重新核对；不得覆盖第三方修改。
自动采用须有固定检查证明的修复或可量化改进，单纯两个候选均退出成功不证明改进。
每份政策限制候选轮次，连续两轮无改进或回退则停止；保留有界历史与中断记录。

本决定细化 R-005 和 R3 的逐次人工审批：在显式预授权政策覆盖的项目开发分支上
可以自动采用/回滚，范围外仍走人工模式。没有授权自动合并主线、push、部署、发布、
修改项目目标或替代最终产品验收。完整文档只是规范与验收映射来源，不自动生成许可。
用户进一步明确：还必须支持依据文档从零开始开发项目。R7 同时交付这一路径及
隔离小项目的真实模型验证：初始只有规范、任务映射和固定验收，没有产品实现；
模型依次建立工程、实现功能、测试和交接，最终停在人工验收。
使用既有 ChatGPT 登录额度，单轮最多 20 分钟、80 次工具完成、16MiB 输出，
环境问题最多一次有明确修正的重试；不购买额度、不改默认配置，结束清理临时凭据。
这是新一轮有界验证，不续用已结束的 R6 额度或把组件夹具冒充模型开发。
Taluvia docset 只读，用于检查接入形状，未授权启动其产品任务或修改原始文档。
真实宿主 hook 的 R6 覆盖缺口仍单独保留。

## R-010：修复 Hook 覆盖、联合试验与新版 alpha 发布

依据：用户在主线整合后询问发布缺口，并明确同意“先修 Hook 覆盖，用固定候选
完成文档开发＋自动 RSI＋恢复＋资源测量联合试验，同时补齐发布材料，然后发新版
alpha”。准入 R8；控制者可以在上述检查和独立评审通过后整合、push 主线、创建新
标签和 GitHub prerelease。不是稳定版验收，也不授权 npm 发布、部署或改写已有标签。

本轮目标版本 `v0.3.0-alpha.1`，可选适配器 `0.3.0-alpha.1`；完整保留的治理 Skill
仍以自身 manifest 的 `v2026.8.13.1` 标识。发布说明须区分整套源码与组件版本，并
明确此前 `v0.2.0-alpha.1` 属于已归档的运行时架构，不提供隐式状态迁移。

先在实际 Codex 版本上验证直接和 code-mode 嵌套工具的事件名、开始前拒绝、有效
开始后执行、恢复/过期/异常拒绝。只修本项目接线及适配器；不借此宣称能拦截宿主
未发出的事件、已启动进程的全部后续副作用、网络托管工具或操作系统旁路。
无网络、无模型调用、有界读取和无轮询的 hook 约束保持；不增加生产逐调用审计日志。

联合试验使用既有 ChatGPT 登录与独立临时项目，固定安装包、文档、验收器、RSI
政策和评估器后开始。最多 30 分钟、120 次工具完成、16MiB 输出；最多两次有明确
环境修正的启动重试，所有片段共用总预算。允许控制者在已完成任务边界终止并同
会话恢复；不替模型提供产品或 RSI 候选实现。开发方法缺陷可以预置为透明测试输入，
须记录注入而不冒充自然发现。真实模型产生候选、实际自动采用、后验及政策内回滚，
与实际产品检查和人工关口绑定；失败保留原证据，不能更换验收标准制造通过。

测量 CPU/IO、调用数、状态写入与临时进程清理；自然压缩只在实际发生时记为已验证。
Taluvia 保持只读，不运行其产品任务；不改用户默认配置，不购买额度或新增 API 计费。
DSH/Claude 保留已验证范围和实验支持，不以 Codex 试验推导全部宿主稳定性。

## R-011：Windows 本机安装与 DSH rc.3 兼容

依据：用户要求先安装到 Windows DSH 和当前 Codex/Work 桌面端，并明确禁止重启
ChatGPT，因为还有其他任务运行。发现本机 DSH `0.2.1-rc.3` 拒绝加载只声明 rc.2
的已发布包后，用户选择“继续补 rc.3 兼容并安装”。

允许在本机保留原发布包，构建独立标识的 `0.3.0-alpha.2` 兼容候选，验证 rc.2
原有路径与实际 Windows rc.3 加载/治理流程后安装；不以版本豁免冒充兼容验证。
本轮不推送、发布、改旧标签或降级宿主，不停止或重启现有应用。配置变更先备份，
保留原插件、模型、权限和其他任务；无项目选择时只安装/注册组件，不把某个项目
计划全局套用，也不准入 Taluvia 开发。按项目绑定文档、计划和 RSI 政策后才启用。

原治理 Skill 不变。Windows 原生 RSI 进程树清理尚未验证，其明确拒绝保持；
可用的完整 RSI 仍限已验证的 POSIX/WSL 路径。组件/确定性宿主安装检查不能冒充
Windows 真实模型开发或长期验收。新包身份单独记录，不挪用 alpha.1 的工件摘要。
