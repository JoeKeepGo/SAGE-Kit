## D-001 单用户、本地、单仓库

**决定**：SAGE-Kit 只服务一个开发者、一台机器、一个仓库；不做账号、组织、租户、RBAC、成员管理、远程共享 API。

**原因**：目标是把个人/小规模 Agent 开发流程做稳；多用户/多机会显著增加权限、隔离、部署和测试成本，且当前没有验证需求。

**后果**：控制面只绑定 localhost；状态存储可以是本地文件/SQLite；跨机协作通过导出/外部系统，不通过内建同步。

## D-002 一个仓库、一个 npm 包、多个入口

**决定**：核心 CLI、Skill 资源、控制面、适配器在同一个 npm 包中；通过子路径/动态 import 分层加载，不拆成多个仓库或多个必装包。

**原因**：降低安装/版本对齐/发布成本；用户只需 `npx`/全局安装一次。

**后果**：需要严格控制入口体积和可选依赖；控制面/适配器不得拖慢 CLI 启动；包内目录边界要清晰。

## D-003 Skill 无状态

**决定**：`SKILL.md` 及 references/templates 只包含指令和资料；不直接持有数据库、不启动守护进程、不隐藏网络调用。

**原因**：Skill 要能跨宿主复用；状态和副作用应由 CLI/控制面承担，便于审计和恢复。

**后果**：Skill 通过 CLI/宿主工具访问状态；需要状态的能力必须显式依赖控制面或文件模式。

## D-004 核心零运行时依赖

**决定**：核心 CLI 目标 `dependencies: {}`；只使用 Node.js 内置模块。控制面所需 SQLite 驱动放 `optionalDependencies`，动态加载。

**原因**：减少供应链风险/安装体积/跨平台问题；核心必须离线可用。

**后果**：不能为了便利引入重型 CLI 框架/ORM；复杂功能放可选层；新增依赖必须记录用途、许可证、体积和替代方案。

## D-005 文件模式默认，控制面可选，不双写

**决定**：默认使用 `.sage-kit/` 文件状态；需要持久队列/反馈/评估时才启用控制面。两种模式只能显式导入/导出，不运行时双写。

**原因**：降低初始门槛；避免两个权威源导致状态分叉。

**后果**：所有写操作必须知道当前模式；模式切换需要迁移命令和只读备份。

## D-006 控制面仅 localhost，不设本地 token

**决定**：控制面 HTTP 只绑定 `127.0.0.1` 并校验 loopback Host；**不设 Bearer token**。信任边界是 OS 用户账户与 loopback，不提供远程/多用户访问。

**原因**：单用户本地工具，要求本机进程再管理一个 token 是额外复杂度；loopback + Host 校验已经阻止远程访问和 DNS rebinding，token 不能有效防御同一 OS 用户下的本地进程。

**后果**：同一 OS 用户下的进程可以读取控制面状态；这是单用户本地工具的接受边界。若未来要远程/多用户访问，另立鉴权与 TLS 契约，不在当前控制面上直接加 token。

## D-007 SQLite WAL 单写者

**决定**：控制面使用 SQLite WAL，单进程写；不引入 PostgreSQL/Redis/消息队列/Kubernetes。

**原因**：单机单用户下 SQLite 足够；减少运维和依赖；崩溃恢复简单。

**后果**：不支持多机/多进程同时写；并发通过单写者 + 任务 lease/worktree 解决。

## D-008 任务 = worktree + lease

**决定**：一个任务对应一个 worktree/分支；同一任务同一时间只有一个执行者（P0 用文件锁，控制面用 lease）；本机 git 操作串行化。

**原因**：避免多个 Agent 互相覆盖；让中断/恢复有明确现场。

**后果**：需要处理 worktree 清理、脏工作区、分支合并；不做分布式锁。

**实现状态（2026-10-24）**：P0 文件模式**尚未实现文件锁/lease**；当前只有 worktree 隔离和 run 记录，不能阻止同一任务并发写。这是已记录的实现差距（`docs/state-and-durability.md`），不是“已实现”能力。

## D-009 四个扩展接口

**决定**：只保留 `HostAdapter`、`TaskSourceAdapter`、`FeedbackSourceAdapter`、`EventSink` 四个接口；Bundle 是格式不是适配器。

**原因**：覆盖宿主/任务/反馈/事件四类真实需求；避免通用插件生态的复杂度。

**后果**：新增集成优先实现接口，不新增插件系统；接口版本化，不匹配时拒绝加载。

## D-010 反馈首期只读

**决定**：v1 只读同步 GitHub/Gitea 反馈；评论/标签/状态写回不在首期。

**原因**：写回需要额外权限、审计、冲突处理；先验证读取/分类/提案链路。

**后果**：团队系统集成以导入为主；写回作为后续单独 ADR。

## D-011 RSI 最高 L2，人工批准发布

**决定**：SAGE-Kit 可观察、提案、评估；发布必须人工批准；不自动合并/发布/重写 Skill 发布版本。

**原因**：自我改进的风险高于收益；人类必须保留最终控制权。

**后果**：没有“无人值守自我进化”；所有发布有审计记录和回滚点。

## D-012 Builder/Evaluator 分离，评估资产受保护

**决定**：候选由 Builder 生成，评估由独立 Evaluator 执行；测试套件、隐藏用例、阈值、发布配置受保护，候选不能修改。

**原因**：防止候选通过改测试/阈值“自证正确”；降低过拟合和奖励作弊。

**后果**：评估流程更重；候选 diff 范围受限；需要独立评估环境和证据记录。

## D-013 Hook 轻量、无网络、无模型、默认 fail-open

**决定**：Hook 只做 brief 注入/事实记录；不联网、不调用模型、不持有状态；失败默认不阻断，`--strict` 例外。

**原因**：Hook 是宿主适配层，不能成为可靠性和安全瓶颈。

**后果**：恢复/调度/评审不能依赖 hook；hook 失败要可观测但不致命。

## D-014 Node.js >=22，ESM，内置能力优先

**决定**：运行时 Node.js >=22；ESM；优先使用内置 `fs/promises`、`child_process`、`fetch` 等。

**原因**：现代 Node 提供足够能力；减少依赖和兼容分支。

**后果**：不支持旧 Node；跨平台路径/信号/权限差异需要测试。

## D-015 不做通用插件系统/事件总线/规则引擎

**决定**：不为了“以后扩展”引入通用插件注册、事件总线、规则引擎、微服务拆分。

**原因**：这些会显著增加抽象和调试成本；当前需求可由四个接口 + 普通函数/模块满足。

**后果**：新需求优先用简单模块/CLI 命令实现；接口不足时先改契约，不先造平台。

## D-016 DSH 是可选宿主适配

**决定**：SAGE-Kit 不依赖 DSH 作为核心；DSH 通过 HostAdapter 接入；其他宿主同理。

**原因**：SAGE-Kit 要跨宿主可移植；DSH 是重要目标但不是唯一环境。

**后果**：核心不能用 DSH 专有 API；适配器负责宿主差异；DSH 适配需按固定版本源码验证。

## D-017 密钥只从环境/密钥存储读取

**决定**：token/key 不写入仓库、状态文件、日志、提示词、UI；只从环境变量/宿主密钥存储读取。

**原因**：本地工具同样可能泄漏密钥到提交/日志/模型上下文。

**后果**：所有日志/错误/事件统一脱敏；需要 Key 的功能由适配器/CLI 读取，不进入 Skill 文本。

## D-018 文档不得把设计写成已实现

**决定**：没有测试/运行证据的能力，文档必须标 `NOT_IMPLEMENTED` / `NOT_EXECUTED` / `NOT_VERIFIED`；静态检查只能证明结构与示例。

**原因**：避免把设计意图误当事实，误导后续实现和用户。

**后果**：每个里程碑有验收证据；发布说明区分“设计/实现/验证”。

## D-019 P0 优先

**决定**：先完成 `docs/p0-acceptance.md`；P0 通过前不做控制面 UI、反馈自动同步、提案/评估/RSI。

**原因**：最小闭环未验证时，上层功能会放大错误和返工。

**后果**：路线图按 M0/M1/M2/M3 推进；任何提前做上层的提议需要明确证据和风险说明。

## D-020 团队系统通过适配器接入

**决定**：不内建团队/多用户功能；外部任务/反馈系统通过 `TaskSourceAdapter`/`FeedbackSourceAdapter`/`EventSink` 接入。

**原因**：保持单用户核心简单；团队需求差异大，适合外部系统承载。

**后果**：跨用户协作依赖外部系统；SAGE-Kit 只做本地任务/反馈的标准化与同步。

## D-021 宿主顺序与 P0 hook 边界

**决定**：Taluvia 主开发环境是 DSH，因此 DSH 适配器优先实现；Codex、Claude Code 其次。P0 只安装 Skill 与受管说明块（`AGENTS.md`/`CLAUDE.md`），不把任何宿主的原生 hook 自动安装写成已实现；`sage-kit hook` 是可被宿主显式调用的命令。

**原因**：DSH 固定版本源码确认了 Skill 目录和 `AGENTS.md` 加载，但未发现可安装的第三方 hook 配置；先把可验证的文件安装做正确，避免把“可能支持”写成“支持”。

**后果**：P0-A13 的真实模型/GUI 会话验收仍必须执行；DSH headless + mock 已验证 Skill 发现/加载。Codex/Claude 的 hook 配置在 M1 按各自公开接口补齐。

## D-022 M2 最小只读 Web UI

**决定**：控制面以 `GET /`、`GET /ui` 提供同源自包含只读 HTML；使用原生 HTML/CSS/JS，不引入前端框架、构建链或 CORS；页面自动读取 `GET /v1/health`、`GET /v1/tasks`；点击任务行直接读取 `GET /v1/tasks/:id` 并展开详情；不提供任何写操作。完整任务板/提案/评估 UI 仍属 M2b。

**原因**：在不扩大控制面攻击面和维护成本的前提下，让单用户能直接看到任务与恢复状态；不把“看板”变成新的默认依赖。

**后果**：`/v1/*` 仍只允许 loopback 访问且无 token；UI 自身不携带数据。若后续需要写入/多用户/远程访问，另立控制台契约，不在本 UI 上直接扩展。
