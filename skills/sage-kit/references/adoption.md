# Adoption

Adoption adds model routing, not a framework runtime.

1. Confirm the user wants SAGE-Kit and identify the project root.
2. Identify current project authority, active SPEC, tests, CI, and acceptance
   owner.
3. Add or select a compact `ACTIVE_CONTEXT` and routing pointer only when the
   project needs them.
4. Choose Light, Standard, or Heavy from actual risk.
5. Reference the canonical `docs/` and optional `contracts/` needed by the
   project; do not vendor the whole framework by default.
6. Prove one real project-native focused workflow and one handoff.

Do not create milestone packages, dispatch records, mirrors, generated packets,
or historical migrations merely to demonstrate adoption. Existing history stays
unchanged. If current authority cannot be identified, report that gap instead
of inferring it from old documents.
